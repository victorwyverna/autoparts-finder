# Autoparts Finder

Клиентское React-приложение для двухэтапного поиска автозапчастей через
публичный API Favorit Parts.

1. По артикулу загружаются доступные производители.
2. После выбора точной пары «производитель + артикул» загружаются исходная
   деталь, аналоги и их складские предложения.

В таблице показаны название, бренд, артикул, тип позиции, склад, цена, остаток и
дата отгрузки. Цена, остаток, склад и дата берутся из `warehouses`, а не из
агрегатных полей детали.

## Стек

- React 19 и Vite 8;
- Redux Toolkit и React Redux;
- Bootstrap 5;
- Vitest, React Testing Library и jsdom;
- ESLint 10;
- JavaScript без TypeScript.

## Требования

- Node.js 22.22.2+, 24.15.0+ или 26+;
- npm 10 или новее;
- доступ браузера к `https://api.favorit-parts.ru`.

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

После запуска Vite выведет локальный адрес. Для ручной проверки можно
использовать артикул `01089`, затем выбрать одного из вернувшихся
производителей.

## Переменные окружения

```dotenv
VITE_API_BASE_URL=https://api.favorit-parts.ru/hs/hsprice/
VITE_API_KEY=00000000-0000-0000-0000-000000000001
```

`.env.example` содержит публичный демонстрационный ключ. Все переменные с
префиксом `VITE_` попадают в браузерную сборку, поэтому здесь нельзя
использовать секретные ключи. Локальные `.env`-файлы игнорируются Git.

Конфигурация валидируется при первом API-запросе. Поэтому production-сборку
можно создать без `.env`, но поиск в такой сборке покажет ошибку, пока значения
не будут заданы на этапе сборки.

## Архитектура

Код разделён по Feature-Sliced Design: высокие слои зависят только от нижних,
а межслойные импорты идут через публичные `index.js`.

```text
src/
├── app/                  # композиция, Redux Provider и глобальные стили
├── pages/home/           # страница поиска
├── features/part-search/ # Redux-состояние и двухэтапный UI-сценарий
├── entities/part/        # нормализация и таблица предложений
├── shared/api/           # HTTP-клиент Favorit Parts
├── shared/config/        # валидация Vite-конфигурации
├── shared/lib/           # технические утилиты и test setup
└── main.jsx              # браузерная точка входа
```

API-клиент возвращает сырой `goods`, доменный слой фильтрует неполные записи,
объединяет дубли и превращает `warehouses` в предложения. Redux Toolkit хранит
статусы обоих этапов, ошибки и `requestId`; ответы устаревших быстрых запросов
игнорируются.

## Допущения API

- Первый запрос использует `number`; второй — точные `number`, `brand` и
  `analogues=on`.
- Поле `error`, неуспешный HTTP-статус, сетевая ошибка или невалидный JSON
  считаются ошибкой запроса.
- Пустая `goods` или API-sentinel с пустыми обязательными полями показываются
  как пустой результат.
- Деталь без `warehouses` остаётся в результатах как недоступная; цена и дата
  для неё не выдумываются.
- Клиент обращается к Favorit Parts напрямую из браузера; работа зависит от
  доступности внешнего API и его CORS-политики.
